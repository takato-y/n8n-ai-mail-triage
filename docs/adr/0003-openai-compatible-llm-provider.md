## 背景

n8n には提供元ごとの AI ノード（OpenAI・Ollama 等のチャットモデルノード）がある。手軽に使える一方、提供元を変えるとノードの差し替えが必要になり、再試行や失敗時の分岐、送信する内容（温度・上限トークン・JSON モード）が見えにくい。

## 決定

- LLM の呼び出しは HTTP Request ノードで、OpenAI 互換の Chat Completions API（`/v1/chat/completions`）に対して行う
- 接続先の URL（`llm_base_url`）とモデル名（`llm_model`）は設定ノード `Set Config` に置く。ローカルの Ollama も同じ形式の API を持つため、この2つを変えるだけで差し替えられる
- 認証が必要な提供元では、HTTP Request ノードの認証に n8n の資格情報（Header Auth）を設定する。API キーをワークフローの JSON に書かない
- 再試行は HTTP Request ノードの「失敗時に再試行」（最大3回・間隔2秒）を使い、最終的な失敗は「エラー出力」に分岐させる

## 結果

- 良い点：開発・テストはローカル LLM（費用なし・外部送信なし）、本番はクラウド LLM、のような切り替えが設定値の変更だけで済む
- 良い点：送信内容と失敗時の扱いがノードの設定として見え、レビューしやすい
- 注意点：提供元ごとの独自機能（ツール呼び出しの細かな差など）は使わない。必要になれば専用ノードへの切り替えを検討する
