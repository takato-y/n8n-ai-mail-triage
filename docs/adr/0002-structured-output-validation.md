## 背景

LLM に JSON での回答を指示しても、前後に説明文が付く、必須項目が欠ける、選択肢にない分類名が返る、といった崩れが起きる。崩れたまま後続に流すと、振り分けが誤る、または後続のノードがエラーで止まる。

検討した方式：

1. LLM 側の機能（JSON モード・出力パーサー）に任せる
2. Code ノードで JSON を読み、スキーマを自前で検証する
3. 検証に失敗したら即座に人の確認へ回す

## 決定

- 依頼時に JSON モード（`response_format: json_object`）を指定したうえで、方式2の検証を必ず行う。提供元によって JSON モードの対応状況が違うため、検証を提供元に依存させない
- 検証項目は、JSON として読めること、必須項目、型、選択肢（enum）、文字数とする。スキーマにない項目は取り除く
- 検証に失敗したら、失敗理由を依頼文に添えて **1回だけ** 再依頼する。それでも失敗したら「要確認」として人の確認に回す
- 再依頼の回数は設定ノードの `max_schema_retries` で変えられる

## 結果

- 良い点：後続のノードは検証済みの値だけを受け取るため、分岐の条件が単純になる
- 良い点：失敗理由（例：「urgency が選択肢にない」）がログに残り、依頼文の改善に使える
- 注意点：再依頼のぶん LLM の呼び出しが増える（最大2回の依頼）。回数に上限を設けて費用と応答時間を抑える
