## 1. 概要

| 項目 | 内容 |
|---|---|
| 対象 | `workflow/ai-mail-triage.json` |
| 実施方法 | `tests/run_live.py` がローカルの n8n にテスト用の写しを作成・有効化し、Webhook に各ケースを POST して応答を照合する。終了後に写しを無効化・削除し、残っていないことを一覧で確認する |
| 入力データ | `tests/cases/TC-*.json`（すべて架空の会社・人物・アドレス） |
| 実施環境 | n8n 2.3.5（Docker）、Ollama・qwen2.5:7b、テスト用の偽 LLM（`tests/mock_llm.py`） |
| 実施日 | 2026-11-15 |
| 結果 | 8件中8件合格 |

偽 LLM は、実際の LLM では狙って起こせない失敗（決まった回数の 503、JSON でない回答）を再現するために使う。受けた要求の回数を数え、再試行・再依頼の回数を確かめる。

## 3. 実施していないテスト

| 観点 | 状態 | 理由 |
|---|---|---|
| Gmail・IMAP トリガーへの差し替え後の動作 | 未実施 | メールボックスと資格情報が必要なため。導入時にテスト用のメールボックスで確認する |
| クラウドの LLM での動作 | 未実施 | API キーが必要なため。OpenAI 互換 API であれば `llm_base_url` と `llm_model` の変更で動く設計だが、実際の応答形式は導入時に確認する |
| 分類精度の評価（多数のメールでの正答率） | 未実施 | 本テストは各分類1件ずつの動作確認であり、精度の評価ではない |
| 本文の文字数上限（20000文字）の境界 | 未実施 | 入力検証の分岐は TC-005 で確認済み。上限の境界値は未確認 |

## 4. 再実行の方法

```bash
# n8n の API キーを環境変数に入れて実行する（キーはリポジトリに置かない）
N8N_API_KEY=... python3 tests/run_live.py            # 全ケース
N8N_API_KEY=... python3 tests/run_live.py TC-002     # 1ケースだけ
```

応答の全文は `tests/out/TC-xxx.json` に保存される（Git の管理対象外）。
